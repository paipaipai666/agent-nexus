# Plan: Per-Session STM Isolation

## Problem

The `ShortTermMemory` (STM) is a **global singleton** — one `deque` shared by all sessions. This causes two bugs:

1. **"Queued" messages**: `isRunning` is a global React state that doesn't reset on session switch. New messages get incorrectly queued.
2. **History loss**: `clearShortMemory()` wipes the global STM when creating a new session, destroying the active session's context. `restoreSession` overwrites the global STM with the target session's snapshot, losing the previous session's live state.

The durable SQLite `conversation_messages` table is already per-session and survives. Only the in-memory working context is affected.

## Architecture Insight

`ChatService` already has per-session version managers: `_version_managers: dict[str, ConversationVersionManager]`. The STM is the only piece still global. The fix is symmetrical: add `_stms: dict[str, ShortTermMemory]` for per-session STMs, and swap them into `memory_manager.short_term` during `send_message`.

This works because `send_message` is synchronous (blocking) — only one agent run executes at a time (enforced by the frontend queue + backend `_is_processing` flag).

## Changes

### 1. Backend: `agentnexus/services/chat.py`

**Add per-session STM storage** (symmetrical to `_version_managers`):

```python
# In __init__:
self._stms: dict[str, ShortTermMemory] = {}
```

**Add `_get_or_create_stm` method**:

```python
def _get_or_create_stm(self, session_id: str, snapshot: str | None = None) -> ShortTermMemory:
    if session_id not in self._stms:
        if snapshot:
            self._stms[session_id] = ShortTermMemory.from_json(snapshot)
        else:
            self._stms[session_id] = ShortTermMemory()
    return self._stms[session_id]
```

**Add `set_session_stm_snapshot` method** (for `restore_session` to store snapshots without mutating global STM):

```python
def set_session_stm_snapshot(self, session_id: str, snapshot: str) -> None:
    self._stms[session_id] = ShortTermMemory.from_json(snapshot)
```

**Modify `send_message`** — swap STM before agent runs, restore after:

```python
def send_message(self, session_id, text, on_run_started=None):
    # ... existing validation ...
    run, events, turn = self.begin_turn(session_id, text)
    # Swap per-session STM into memory_manager
    saved_stm = self._memory.short_term
    session_stm = self._get_or_create_stm(session_id)
    self._memory.short_term = session_stm
    try:
        # ... existing agent run logic ...
    finally:
        self._memory.short_term = saved_stm
        # ... existing cleanup ...
```

This ensures:
- `TurnRuntime.__init__` reads correct `_stm_start_count` from per-session STM
- Agent reads/writes per-session STM during the run
- `TurnRuntime.persist_snapshot()` computes delta from per-session STM
- Global STM is restored after the run completes

### 2. Backend: `agentnexus/server/routes/chat.py` — `restore_session` (line 243)

**Stop mutating global STM.** Store snapshot in `ChatService._stms` instead:

```python
# BEFORE (destructive):
runtime.memory_manager.short_term._messages = restored._messages
runtime.memory_manager.short_term._summary = restored._summary

# AFTER (non-destructive):
runtime.services.chat.set_session_stm_snapshot(session_id, snapshot)
```

### 3. Backend: `agentnexus/server/routes/memory.py` — `clear_short_term_memory` (line 99)

**Make session-aware.** Accept optional `session_id` parameter:

```python
@router.post("/short/clear")
def clear_short_term_memory(session_id: str | None = None):
    if session_id:
        runtime.services.chat._stms.pop(session_id, None)
    else:
        # Legacy: clear global STM (backward compat)
        runtime.memory_manager.short_term.clear()
    return {"status": "cleared"}
```

## What This Does NOT Change

- `AppRuntime.build()` still creates one `MemoryManager` — the global `short_term` is used as a fallback/scratch space
- `MemoryManager` API is unchanged — `append()`, `maybe_compact()`, etc. all work on `self.short_term` which gets swapped
- The TUI path is unaffected (it already uses single-session mode)
- `agent.run()` signature is unchanged — it still receives `memory_manager`
- SQLite `conversation_messages` table is already per-session — no changes needed
