# 能力缓存与协议展示修复

## 已确认范围

目标是复用已确认的模型能力，按原生工具、JSON Mode、提示词 JSON 的顺序尝试协议，并阻止控制协议进入用户可见输出。未知、支持、明确不支持和临时探测错误必须分开处理。限流、超时和网络错误不降级能力。普通工具能力的成功证据不能被后续并行探测失败撤销。

缓存按服务地址、模型、认证身份区分，跨客户端与进程复用已保存结果。思考强度、输出预算不改变普通工具能力的缓存身份。已确认结果不按固定 24 小时过期。手动刷新可重新确认能力，临时失败持久化退避信息并保留已有证据。兼容读取原有缓存的成功值，旧版含义不明确的 False 恢复为未知；密钥不明文落盘。

未知模型的实际任务先使用原生工具协议，不先发送额外的 noop 探测。明确不支持当前协议后才降级，显式配置关闭的能力按配置跳过。请求参数与策略选择必须采用同一能力状态。

展示只接收解码后的说明、答案和工具事件。工具参数保留在工具卡片。普通文本、用户要求的 JSON、取消和历史回放继续可用。保留已完成的 tooltip 修复。

## 非目标与回滚

不硬编码 Agnes 能力，不增加启动探测等待预算，不修改用户配置或聊天数据库结构。实现分为能力状态与缓存、请求降级、协议展示三个可单独验证的单位。每个单位可连同对应测试回退，缓存读取支持旧格式。

## 类型与边界

`ModelCapabilities` 保留现有有效布尔值，并显式记录未知字段。未知的普通工具与 JSON 协议允许尝试，未知的并行能力不主动启用。

`CapabilityDiscovery` 保存每项已确认值及最近临时失败的退避时间。成功证据立即写入，后续探测失败只记录本次失败。缓存读取负责外部数据验证，策略函数只消费已经验证的能力状态。

`AgentLLM` 的实际请求记录成功能力及明确的协议不支持错误。`last_unsupported_capability` 区分协议拒绝与传输失败，Agent 据此逐级切换。展示分类在 Agent 事件边界完成，原始控制 JSON 不作为普通文本 token 发出。

- [x] Frame：确认需求、现状、失败链路与写入归属。
- [x] Fan out：分配协议展示与能力处理两个互不覆盖的实现范围。
- [x] Aggregate：检查实现，合并运行行为与集成回归。
- [x] Report：记录最终结果、限制与复现命令。

根任务拥有 `core/capabilities.py`、`core/capability_discovery.py`、`core/llm.py`、`agents/decisions.py` 的策略选择、相关能力测试与记录。协议任务拥有 Agent 的流式输出、必要的协议解析和展示适配、以及专用测试。共享文件修改前先协调，提交需要用户另行授权。

验证包括部分探测成功后限流、跨进程缓存、配置切换、未知模型原生请求、明确不支持后的降级、传输失败保持档位、JSON 协议不外露、普通 JSON 保留、实际 TUI 展示和恢复。手动后台发现保留总预算约束。行为修复通过失败测试确认，再运行对应回归。新增的启动零探测用例同时约束现有界面行为。
