# 启动性能修复与复测

2026-10-21，Windows 11，Python 3.13.6，16 个逻辑处理器。

修复代码版本：`f39e834715facdf50ec8efe143d0d7fc190e4e42`。测量时包含该提交的全部生产代码。

TUI 启动到按键回显的中位数从 **15.253 秒降至 2.390 秒，减少 84.3%**。修复后十次测量均低于 3 秒。首次读取能力接口的中位数从 **70.774 秒降至 5.968 毫秒**。

## 根因

基线提交为 `27529a0904896d883d9c92137a380c64eec3f246`。`ChatScreen.on_mount()` 同步刷新模型面板，读取 `AgentLLM.capabilities` 时触发两次串行远程探测。这些请求在 Textual 主线程执行，三次测量分别耗时 12.993、5.966、17.995 秒，占启动时间的 72%–89%。同一批测量中，`AppRuntime.build()` 仅耗时约 1.03 秒。

能力接口也读取这个属性，首次查询出现 5.438–71.634 秒等待。原缓存仅在进程内生效，持锁范围包含网络请求，重启丢失结果，不同模型的探测也会互相等待。探测复用聊天请求的超时和重试策略，没有独立的短总预算。

## 改动

1. 能力属性、TUI 面板和 GET 接口只读取配置与本地缓存。真实任务执行前通过显式操作确认未知协议。
2. 成功结果缓存 24 小时，并持久化到独立目录。缓存标识包含精确模型名、端点、凭证和能力配置的摘要。损坏、过期或非法缓存自动重建；失败保持未知，进程内退避 30 秒。
3. 同一配置合并探测，不同模型可以并行探测。模型切换与本地快照读取互斥，探测使用捕获的模型参数，网络等待不持有该锁。
4. TUI 首次绘制后启动后台探测；桌面组件通过 POST 发起探测并轮询 GET。接口增加 `source` 和 `discovery_status`，界面区分未知、探测中、成功和失败。
5. 两次探测共享最多 5 秒的网络总预算，覆盖连接、响应头和流读取。OpenAI 探测使用独立连接并关闭 SDK 自动重试，期限到达时关闭连接。普通聊天保留原有连接池和超时配置。

未修改用户模型布尔配置，未删除记忆、RAG、MCP、技能或后台 embedding 预热。

## 测量结果

所有启动测量均从父进程创建子进程前开始。基线各 3 次，修复后各 10 次，串行执行。下表为中位数。

| 指标 | 基线 | 修复后 | 修复后范围 |
| --- | ---: | ---: | ---: |
| TUI 进程创建到按键回显 | 15.253 秒 | 2.390 秒 | 2.294–2.798 秒 |
| TUI 内部 runtime 构建 | 1.029 秒 | 1.135 秒 | 见原始事件 |
| 后端进程创建到 `/health` 200 | 2.217 秒 | 2.167 秒 | 2.033–2.601 秒 |
| 首次 GET `/api/config/llm/capabilities` | 70.774 秒 | 5.968 毫秒 | 3.230–36.556 毫秒 |
| 再次 GET 能力接口 | 15.749 毫秒 | 18.356 毫秒 | 3.201–67.929 毫秒 |
| POST `/api/config/llm/capabilities/refresh` | 无此接口 | 10.043 毫秒 | 3.461–27.834 毫秒 |

修复后每次首次 GET 均返回 `unknown/unknown`，POST 返回 `unknown/probing`。这证明展示请求完成时没有等待远程探测。缓存成功后的状态更新和协议执行由本地真实 HTTP 集成测试验证。

后端健康检查原本就在约两秒内可用，这次收益主要来自消除 TUI 挂载和首次能力查询中的远程等待。未把能力接口原来的 70 秒延迟称为整个桌面启动时间。

## 复测

在仓库根目录运行：

```powershell
rtk proxy python scripts/benchmark_startup.py --target tui --repeat 10 --output startup-tui.json
rtk proxy python scripts/benchmark_startup.py --target server --repeat 10 --output startup-server.json
```

脚本复制当前配置、SQLite 在线备份与技能目录到临时 `AGENTNEXUS_HOME`，不复制能力缓存。每个样本都启动新进程，结束后删除临时副本。测量过程使用当前配置的远程模型进行后台探测；不会提交用户问题。可用 `--home` 指定其他配置目录。

TUI 运行真实 CLI、runtime 和 Textual headless driver。输入框获得焦点后投递 `Key('x', 'x')`，直到输入框文本出现该字符才记录完成，不等待 CPU 空闲。HTTP 测量运行真实服务，以 25 毫秒间隔轮询健康检查。复测通过实际的 `/api/runtime/shutdown` 结束服务，二十个修复后样本的退出码均为 0。基线 HTTP 样本的退出码 1 来自旧测量脚本主动终止服务，不表示启动失败。

这是冷进程、热文件缓存测量，保留操作系统及模型文件缓存。TUI 的真实终端绘制、Electron 首帧及历史会话恢复不在测量范围内。修复后端代码未重新打包到已安装的桌面程序；安装版需要重新构建才能获得这些修改。样本量不足以报告 P95 或 P99。

## 验证范围

集成测试使用本地可控 HTTP 服务和真实 provider，覆盖展示零网络调用、慢端点下 TUI 输入、异步状态更新、真实任务工具协议、跨进程缓存、凭证隔离、损坏缓存重建、同键合并与跨模型并行、切换模型时的快照竞争、慢响应头与持续流的截止期限、两次请求共享预算，以及超时后连接和线程回收。

相关 Python 回归还覆盖流式取消、思考参数、provider 编解码、TUI 生命周期与附件处理。旧测试使用明确的客户端配置和隔离的连接池，避免把任务响应当作探测响应，或在不同用例间共享熔断状态。
